Case study 01 | Healthcare AI | Production at Datycs

Making medical chart review faster and cheaper with LangGraph

THE PROBLEM

Health plans have to check patient charts against HEDIS quality measures, which is slow, careful work. Our first version used CrewAI agents that ran one after another and called an LLM for every check, even when a patient was already excluded from a measure early on. That meant wasted calls, slow runs and no easy way to pick up a run that failed halfway.

MY APPROACH

I redesigned it as a five-step LangGraph pipeline with one typed, shared state. The key idea is exclusion first: if a patient is excluded, we stop right there without spending any more LLM calls. For everyone else, the pipeline fans out across clinical entities in parallel using the Send API. Checkpointing means any run can resume exactly where it stopped.

Load chart → Exclusion check (fast exit) → Parallel fan-out per entity → Extract & verify → Compliance decision
RESULTS
15%fewer LLM calls per chart
Millionsof clinical records processed by our services
5nodes sharing one typed state
100%of runs resumable from a checkpoint
TRADE-OFFS

Exiting early only works if the exclusion step is trustworthy, so I measured it against annotated ground truth with precision, recall and F1 before relying on it. Running entities in parallel is much faster but needs care around API rate limits and keeping the shared state consistent.

WHAT I'D DO NEXT

Extend the pipeline to more HEDIS measures, and add confidence scores so that only borderline charts go to a human reviewer while clear-cut ones flow straight through.

Case study 02 | Agentic AI | Open source

Kaizen Agent: a triage agent that needs less help the more it's used

THE PROBLEM

Failure analysis teams see the same kinds of problems again and again, yet each one usually gets the full, expensive treatment: a fresh LLM analysis and a person checking the result. I wanted an agent that remembers what it has already solved, checks its own work, and only asks a human when it truly needs to.

MY APPROACH

Built on LangGraph 1.x. A memory gate routes familiar cases down a cheap path. New cases go to an analyst agent, then a second, adversarial reviewer agent that tries to poke holes in the answer. Uncertain results pause with interrupt() for a human, and every approved answer goes back into memory. Checkpointer-backed time travel lets me replay any decision to debug it.

New failure → Memory gate (reuse if seen) → Analyst agent → Reviewer agent → Human check (if unsure) → Saved to memory
RESULTS
20%fewer human escalations over time
2agents: an analyst and an adversarial reviewer
1human checkpoint, only when the agent is unsure
TRADE-OFFS

Reusing past answers saves a lot, but a memory can be confidently wrong. The reviewer agent and the human checkpoint are there to catch that, at the cost of some extra calls on new cases. A second agent also adds latency, which I only pay for when the memory gate can't answer.

WHAT I'D DO NEXT

Let old memories expire or get re-checked so stale answers don't linger, and teach the agent when it's safe to skip the reviewer on easy cases to save time and cost.
